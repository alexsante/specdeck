Spec Deck

How worktrees are read

  • Discovery: git worktree list --porcelain from the opened folder. Read-only, like everything else. Each worktree gets its own file watcher.
  • Opens on the folder you opened, at whatever branch it has checked out. The sidebar's Worktrees list and the switcher in the header move to a related worktree; the project then reads as if you had opened that folder.
  • Nothing goes unseen: a hint bar counts the specs that exist only in other worktrees, and a row says when another worktree has a different copy of its spec. Both switch on click.
  • Now working on shows the viewed worktree's .specify/feature.json. The other worktrees' features appear as cards underneath.

Rules this touches

  • Waiting on me also counts a Done spec that has uncommitted edits in any worktree (27450 here).
  • Timeline: one bar per spec. When copies disagree, the bar follows the copy on the spec's own branch.
  • Pull now (FR-070) runs in the worktree being viewed, with the same refusals.
  • Review comments (FR-060) compare the file in the worktree that has the PR's branch checked out.
  • Prunable worktrees (folder deleted) stay listed and dimmed. The app copies git worktree prune; it never runs it.

Decided 2026-11-09

  • Default: open on the target folder's own branch, with an option to switch to a related worktree. No combined all-worktrees list.
  • Labels: worktrees are named by folder and branch only, whatever tool created them.
  • Waiting on me: yes, an uncommitted edit in a worktree puts a Done spec there.
  • Timeline: one bar per spec.
